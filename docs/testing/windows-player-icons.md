# Windows 播放页：歌词、评论和桌面歌词的状态图标

在桌面宽布局下打开一首能看评论的网易云歌曲。启用评论功能，先关闭桌面歌词。冷启动后第一次打开「正在播放」，不要预先点歌词按钮。

| 操作 | 歌词（引号气泡） | 评论（文字气泡） | 桌面歌词（字幕框） |
| --- | --- | --- | --- |
| 首次进入，默认显示歌词 | 实心 | 线框 | 线框 |
| 进入评论 | 线框 | 实心 | 线框 |
| 返回歌词 | 实心 | 线框 | 线框 |
| 开启桌面歌词 | 实心 | 线框 | 实心 |
| 关闭桌面歌词 | 实心 | 线框 | 线框 |

歌词和评论至少往返两次，桌面歌词也要关掉后再次打开。检查**按钮本身仍在且可点击**，而不只是面板内容切对了；同一个按钮两态的轮廓和位置不应改变。

用开发版复验时，每一步都保留两份证据：`enji ui inspect` 中应各有一个 `now_playing.lyrics_*`、`now_playing.comments_*`、`now_playing.desktop_lyrics_*`；同时对照该步操作后新生成的 `main-1.png` 工具行。前者能发现按钮消失，后者才能看出是否实心。将测试实例的 `BERN_SNAPSHOT_DIR` 指向本轮的空目录即可得到窗口自身的 XAML 渲染，不需要截取整个桌面。

图形采用微软 [Fluent System Icons](https://github.com/microsoft/fluentui-system-icons/tree/4e8620a7c6ba5fba3f3f3f6908dd06b3a9332be6/assets) 的 Comment Quote、Comment Text、Subtitles，各用同一款 20 × 20 图标的 Regular 和 Filled 版本。前两组是气泡，字幕框没有气泡尾巴。

切回时，Windows 原生 `PathIcon` 可以共用路径数据，但每个控件必须创建自己的 `Geometry`。只验证首次显示会漏掉控件重建时的错误。

## 真机对照

在 Windows 11（26200.9974，WinUI 3）上，开发中的第一个候选缓存了 `Geometry`。同一进程内，首次歌词、首次评论、切回歌词三张工具行裁图分别有 7、7、5 个按钮：页面内容切回了，但歌词和评论都不再出现在可操作控件里。当时观察到两条 `bern: effect: 参数错误。`，没有数值错误码。这是候选版的回归，不是 0.3.19 最初的字形映射问题。

在同一台物理机上，只把缓存改为每个图标各建一份 `Geometry`（Bern `dbaff1a8`），再从冷启动开始复验九步。首次进入歌词即为实心；两次切到评论、两次切回歌词，以及两轮桌面歌词开关，均与表格一致。九张原生裁图每张都有七个按钮，三个目标控件每步都在；回到同一状态时三个图标的像素与前次一致。该进程正常退出，标准错误只有 WinUI 3 后端启动信息。

最后用 [Bern 合并提交 `3b8890eb`](https://github.com/AimesSoft/Bern/commit/3b8890eb97d43f34c4ad0369d6675820a251b3de) 对应的完整源码树 `9d8e3f57` 重新生成并编译 Windows 程序。另起进程从冷启动复验表中五步：三个图标与上轮同态的像素一致，七个按钮始终可见，未出现 `effect` 错误。已核对合并提交与实测候选的 Git 树对象完全相同。实跑覆盖 Windows 11 的 WinUI 3；系统 XAML 回退前端编译通过，未在 Windows 10 真机运行。
