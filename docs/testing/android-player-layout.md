## 首轮：只验证尺寸稳定，不代表视觉合格

用户指出首轮窄屏截图中封面过小且偏左，歌词占了四行、间距过大。首轮仅以尺寸不跳动为通过标准不充分；以下测量保留为旧布局记录，不作为最终视觉验收结论。

通过应用 CLI 选择歌词、开关注音/译文，并用 Android UI Automator 读取真实布局边界、截取模拟器截图。跳转歌词会异步恢复播放，最终测量先等待播放状态稳定再暂停；以下记录均为同一首歌（2623442905，草薙寧々《夜に駆ける》），没有把自动切到其他歌曲的早期采样混入最终结果。

| 屏幕 | 状态 | 封面边界（物理像素） |
| --- | --- | --- |
| 1080×2424 | 短句、无注音句、长句、关闭译文、关闭注音 | 全部 `[74,290]–[980,1196]`（906×906） |
| 800×1800 | 短句、长句、关闭译文、关闭注音等五组 | 全部 `[74,285]–[361,572]`（287×287） |

窄屏长句“ありきたりな喜びきっと二人なら見つけられる”实际显示两行；带注音的当前句高度从短句的 77 像素增加为 154 像素，封面尺寸和位置仍不变。两行当前句、注音、单行省略译文和下一句均已查看截图，没有挤入进度条或播放控制区。关闭注音后同一双行句高度为 106 像素，封面仍不变。

测试结束已用 `adb shell wm size reset` 恢复默认分辨率。

## 按用户截图纠正后的布局

首轮的问题不是封面是否稳定，而是为过多歌词行及间距牺牲了封面。现改为：

- 当前句始终最多一行；显示译文时，第二行只显示译文，不同时显示下一句。
- 未显示译文时，第二行显示下一句，最多一行。注音保留，超长文字省略。
- 歌词区从 136 缩至 68，内部间隔 3→2、上下留白 8→4；保留紧凑而稳定的两行预算，避免换句时封面再次跳动。
- 控制区间隔 14→6、上下留白 18→8，封面区移除默认的 8 点子项间隔。
- 封面放在带两侧弹性空间的横排中，短屏时缩小后仍在整行中央，而非偏向左边。

使用同一 800×1800 分辨率、同一首歌、同一句长歌词重建 APK 并安装后实看：封面由 287×287 增至 **559×559**，边界 `[120,285]–[679,844]`。当前句与译文只占两行，下一句不再同时出现。

关闭译文、关闭注音，以及切到短句后，封面仍保持相同边界。第二行在译文关闭后改为下一句，带注音的下一句也未侵入控制区。已查看窄屏长句及恢复 1080×2424 后的截图；最终 crash buffer 仍为空，未修改播放列表实现。本轮安装时首次启动命令误用了运行时类名，纠正为应用的 `.MainActivity` 后正常启动。

原始截图及 XML 在 `target/diagnostics/android-player/compact/`；分辨率与歌词设置已恢复默认。

## 证据与边界

原始测量、UI XML、截图及循环记录保留在本机 `target/diagnostics/android-player/`，不提交构建产物与完整状态数据。
