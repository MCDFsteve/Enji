# Android 模拟器播放页回归

日期：2026-11-11。

## 环境与构建

- 修复提交：`3142fd4`；Enji 0.3.10，Bern / bern-cli 固定为 `47820993b1f519b5e4e754a1597867da39c2ee54`（0.1.15）。
- 复用 `Enji_Test` ARM64 模拟器，Android 16 / API 36，默认分辨率 1080×2424，字体缩放 1.0。
- bern-cli 使用 Rust 1.99 安装到临时目录，没有覆盖电脑上的旧 CLI。所有 Cargo 编译复用 `/Library/Afolder/RustProject/Bern/target`。
- `bern run --target android` 完成 Rust、Android 工程构建、APK 安装和启动。`bern run` 随后持续输出 logcat，这不是构建尚未完成。
- 模拟器原先未连接 Wi-Fi；连接 AndroidWifi 后完成在线搜索和播放。

## 封面不随歌词高度变化

通过应用 CLI 选择歌词、开关注音/译文，并用 Android UI Automator 读取真实布局边界、截取模拟器截图。跳转歌词会异步恢复播放，最终测量先等待播放状态稳定再暂停；以下记录均为同一首歌（2623442905，草薙寧々《夜に駆ける》），没有把自动切到其他歌曲的早期采样混入最终结果。

| 屏幕 | 状态 | 封面边界（物理像素） |
| --- | --- | --- |
| 1080×2424 | 短句、无注音句、长句、关闭译文、关闭注音 | 全部 `[74,290]–[980,1196]`（906×906） |
| 800×1800 | 短句、长句、关闭译文、关闭注音等五组 | 全部 `[74,285]–[361,572]`（287×287） |

窄屏长句“ありきたりな喜びきっと二人なら見つけられる”实际显示两行；带注音的当前句高度从短句的 77 像素增加为 154 像素，封面尺寸和位置仍不变。两行当前句、注音、单行省略译文和下一句均已查看截图，没有挤入进度条或播放控制区。关闭注音后同一双行句高度为 106 像素，封面仍不变。

测试结束已用 `adb shell wm size reset` 恢复默认分辨率。

## 歌词页播放列表

- 在歌词页实际点击右下角 Queue，弹层显示歌曲、封面和时长，截图已查看。
- 用 `adb shell input tap` 和系统返回键连续完成十轮打开/关闭，每轮等待布局/关闭动画完成，再读取弹层状态。
- 第五轮滚动列表，随后关闭并继续开关。
- 最后实际点击列表中的另一首歌，应用状态确认切到 2623126899（小豆沢こはね），`queue_at=2`、`playing=true`。
- 全程应用进程 PID 均为 3839，没有靠崩溃重启恢复；Android crash buffer 最终为空。

早期循环脚本在按返回后立刻读取状态，曾把尚未结束的关闭动画误判为失败。等待 UI Automator 布局稳定后，十轮全部通过；该次误判没有崩溃日志。

## 证据与边界

原始测量、UI XML、截图及循环记录保留在本机 `target/diagnostics/android-player/`，不提交构建产物与完整状态数据。

本轮验证的是修复后的真实 Android 模拟器应用，没有回装旧 APK 复现原崩溃，因此不能把新版本未崩溃当成旧版异常堆栈的证明。没有测试实体手机、更大系统字体、Android TV、iOS 或 Windows，也没有运行全工作区测试。
